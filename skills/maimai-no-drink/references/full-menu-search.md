# 任意餐品需求与候选覆盖

## 获取和检索

每次新场景使用 query-meals 完整返回的 meals；不得按历史食品编码或几种中文关键词截断。套餐名称可能不包含目标食物，因此检查菜单上每个条目的 query-meal-detail（含轮次 choices）；分页如有则读完。相同门店/渠道/时段的一次会话可以复用详情，但准备报价时刷新菜单可用性和价格。另一门店或时段不可复用。

原生工具不可见时，运行 `python <技能目录>/scripts/menu_index.py scan <本地输出JSON>`，从标准输入传入已发现参数的门店 context。脚本只查菜单及详情；任何失败停止并保留未读列表，不保存 Token、地址和手机号。该输出可包含菜单服务图片链接，不要自动下载或用于公开产品图。

运行 `python <技能目录>/scripts/menu_index.py find <JSON> 土豆泥 大鸡排` 可检索。索引覆盖菜单名称、详情名称和全部套餐子项。脚本只做规范化文字匹配，不把俗称替换成某个商品。助手结合完整索引理解俗称：多个可能匹配则列少量真实候选确认；例如“大鸡排”不能自动变成“鸡排堡”。未命中时还要检查语义近似名称；只有所有详情读完后才说“本店本渠道当前菜单未找到”，不能说全国麦当劳都没有。

用户明确要的食物缺失时，先说明，询问是否接受实际存在的替代；不能用相似食物的价格回答原需求。鸡翅两块/四块、鸡块五块/十块、薯条大小都需对齐单位。套餐子项未作为单品售卖时，不伪造可单点 SKU。

## 构建需求相关候选

1. 默认饮料模式 exclude。家里有饮料、不要可乐等表达，在本产品中按“不购买任何饮料”处理；如果用户明确想喝另一种饮料或允许附带，则按其说明处理。有歧义且影响比较时确认。
2. 建立目标餐品、份量、允许替代清单。精确需求作为基准；多余食物不能偷换成同份量优惠。用户未表态时，额外小食方案单列，不替代精确需求结果。
3. 建立无券单点基准（目标不能单点时记录基准不存在）。遍历全部详情，找到任意轮次包含目标食物的套餐，以及可覆盖目标的固定小食组合。建立 `目标SKU -> 父套餐` 索引，不仅按套餐名搜索。
4. 对每个相关套餐检查所有合法轮次选项。饮料包括水、奶、果汁、咖啡、茶等，不是只有可乐。名称/类别不能确认是否饮料的条目先核实，未知不能按无饮料计入。不要以可去冰/去糖视为可取消饮料。必选饮料轮次若没有明确非饮料替代则排除整套餐。
5. 展开合法无饮料配置，包括非默认替换；每轮严格满足 minQuantity/maxQuantity 及子项 maxQuantity，保留默认特制参数。缺失约束、未知嵌套套餐或无法确认份量时列为未解决，不编造配置。
6. 组合多个相关套餐和补齐单点，使每项目标数量满足要求；不能仅比较“一个套餐+单品”。去重相同实际购物篮。用目标数量限制枚举；额外主食不得默认强加。菜单展示价不能作为最终排序依据或未经证明的剪枝下界，特别是有整单优惠时。
7. 查询同门店可用券，检查券适用商品是否在主菜单之外，必要时取得其详情。允许使用现有券，不自行领券/买会员/花积分。只有官方确认合法并试算成功的叠加进入候选；不确定的叠加保持未知。
8. 每个最终候选单独 calculate-price；完整费用核验后排序。最多一次批次100个核价候选或5分钟，任一达到则保留未核价候选和预算停止原因，交付已查结果并说明剩余范围。禁止为赶进度把未核价候选当作价格更高。中途认证失败/限流立即停止。

## 交付搜索覆盖清单

每次结果附简短覆盖说明，并在需要复查时保存无个人信息的报告：

```
menu_entries / details_read / failed_details
requested_items: 原话、确认名称、SKU、实际份量、未匹配项
relevant_bundles / configurations_checked / unknown_configurations
candidate_baskets / quoted_baskets / failed_quotes / pending_baskets
coupon_count / coupon_candidates_checked / unresolved_coupon_rules
stopped_reason / store_channel / queried_at
```

“完整菜单已读取”不等于“所有组合与优惠已穷举”。只要有未读详情、未解析配置、未核价候选、券规则未知或预算停止，就使用“本次已查询方案中最低”。即便有界候选全部核价，也只声明该门店、时段、目标份量和已明确优惠条件下的范围，不声称全国/全渠道最低。

输出先回答：无饮料可选方案、实付、与同份量单点基准的差价。没有单点基准时不计算节省。没有优惠如实给单点；没有满足条件方案时说明原因。在线体验页是固定历史样例，与 Skill 实时完整菜单检索的能力范围分开。
